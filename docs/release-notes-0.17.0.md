# 0.17.0

**Feel the bus on the trackpad.** `aivoicebus sound on` makes a Mac's Force Touch trackpad tap, in a pattern of its own, when a message is sent (`tick`), when one arrives for a session on the machine (`double`), and when one is taken back (`fall`). The sound comes from the trackpad's haptic motor, not the speakers, so the Mac can stay muted. It is off until the person on the machine turns it on, and a machine taps once per message however many sessions read it. It stays still by itself while the Mac is in a Focus (Sleep, Personal, Do Not Disturb, Work, a Focus of your own, or one shared from an iPhone): macOS keeps which are on, and aivoicebus reads only their identifiers, never the Focus settings. `sound focus` shows which are on and `sound focus ignore` taps through them. Quiet hours silence it too, except that an urgent message arriving still taps. `sound test` plays each pattern, `sound set EVENT PATTERN`, `sound level` and `sound toggle` change it, and `AIVOICEBUS_SOUND=0` or `1` decides for one process. macOS only.

The motor is reached through a private macOS framework that a static Go binary cannot call, so the first `sound on` or `sound test` compiles a small C helper, embedded in the binary, with the Mac's own compiler into `~/.config/aivoicebus/bin`. That needs Xcode or the Command Line Tools once; aivoicebus checks they are there first, so a Mac without them never gets the installer dialog, and nothing is downloaded. See the reference's Sounds section.

**Updates that do not wait for a session.** Auto-update (opt-in, `update --auto on`) used to start only from a session start, so a machine nobody opens an agent session on never updated. The worker and `forward --webhook` now check about hourly, and `update --auto tick` does the same check for cron or launchd. A machine waits its own fixed share of six hours after it first sees a newer release, so the fleet does not install at once. After the swap the installed binary must run and report the release it was installed as, or the previous binary is put back and that release is left out. `update --auto status` shows the last periodic check. With auto-update off, none of this asks the nodes anything.

**Named signers.** Each built-in release key now says which machine holds it and the release that first carried it. `release verify` says which signer signed, `release keygen` and the new `release pubkey` write the public half beside the key, and `who --has release-key` lists the machines that can sign. `release pack` refuses to sign release X with a key whose first release is X or later, because machines still on an older release would reject it. See Signers in the releasing guide.

This is not a protocol change and touches no wire-format file: nodes and older clients need nothing. A machine only changes behaviour when its person turns on sounds or automatic update.
