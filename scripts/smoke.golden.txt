Usage of send:
  -budget-chars int
    	start a conversation that holds at most this many characters of messages in all: the nodes refuse a message that would pass it, an [end] always goes; bounds what it costs
  -deadline duration
    	start a conversation that closes this long after it starts (e.g. 1h): the nodes refuse later messages in it, an [end] always goes
  -detach
    	with a deadline: send, remember it and return at once; watch reports it when it passes, status ID shows it any time
  -dry-run
    	check the message and say who it would reach and what it would cost, without sending
  -escalate string
    	with --reply-by, when nobody read it by the deadline: machine (an urgent reminder to the live sessions on its machine), person (ask-human), or machine,person in turn
  -escalate-wait duration
    	with --escalate person: how long to wait for the person's answer (0: ask and return) (default 10m0s)
  -file string
    	send a file: it is encrypted here, held for 5 minutes (read once) by the pipe or by a node (--via), and the message carries the link; the reader runs: aivoicebus get ID
  -force
    	send despite the guardrails (urgent to many sessions, a long body to many sessions, one session not seen for 30m)
  -json
    	print the result as JSON
  -keep
    	with --file: let several sessions read the file (it is not burned by the first read)
  -kind string
    	question | answer | task | claim | end | lease | progress: a question to several sessions stops being delivered once someone answers it (an answer needs --re)
  -max-turns int
    	start a conversation that holds at most this many messages (claims not counted): the nodes refuse more, an [end] always goes; stops two agents from going on for ever
  -meta value
    	with --file: seal a key=value inside the file's encrypted payload for the reader (repeatable; any keys: it is open data the reader may use or ignore; the file name, size and sha256 are sealed with it)
  -need-by string
    	--reply-by as a time: <TIME>Z (UTC), <TIME> (this machine's clock) or 2026-10-22T<TIME>Z
  -open-link
    	with --file: put the key in the link as before instead of sealing it for the recipient machine (for a reader on 0.10.4 or older, or the pipe's own p save): whoever reads the board can then fetch the file once
  -prio string
    	fyi | ask | urgent (default ask, or fyi when the text says FYI/DONE/no action needed and asks nothing): fyi is only counted at session start, urgent is shown first
  -private
    	seal the text to the recipient machine's key: nodes and every other reader see only that a private message went there (one machine or session, not a selector or all)
  -queue
    	send a selector message even if no session seen in the last 24h matches it, or one to a session not seen for 30m (it waits for one that starts later)
  -quiet-after duration
    	with a task and --wait-reply: say so once when the session that took it says nothing (no progress, answer or end) this long, and with --fallback give it to the next machine; 0: never (default 10m0s)
  -re string
    	reply to message id (or its first characters, if they name one message)
  -reply-by duration
    	wait this long (up to 24h) for a reply, then say whether anyone read the message: read by 0 of 1 is exit 8 (silence is not consent), a reply is exit 1, read and no reply is exit 0; ends early on a reply
  -tail string
    	point at a live log held by tail server: a stream name, or the word new for a fresh one; feed it with: cmd | aivoicebus tail push --stream NAME
  -test
    	send in the test lane: it reaches only sessions that opted in (AIVOICEBUS_TEST=1), is never put into a hook's context or a replay, is left out of stats, view and export, lives at most 10 minutes and is purged; a reply to a test message is one already. Read the answers with inbox --test
  -thread string
    	thread id (default: new, or the reply's)
  -to string
    	all | host | host/agent | */agent | host/* | @repo=x,branch=y | @here | @+group (see: aivoicebus usage); default for --re: whoever wrote that message
  -trust-role
    	use a role alias (@build) that nobody pinned and one session claims; never for urgent or file/log sends. Better: aivoicebus role pin build 'host/claude.*'
  -ttl string
    	how long the message stays relevant, e.g. 90m, 2h, 3d; expired messages are not delivered. Default: 1d for fyi and 3d otherwise when it can reach several sessions, never for one session
  -until duration
    	with a task (the offer): wait up to this long (1m to 24h) for someone to take it; untaken, its ttl is this so the nodes stop delivering it, and the command says it is not being done (exit 3)
  -via string
    	with --file: pipe (the pipe server, default) or node (this mesh's own nodes hold it); default $AIVOICEBUS_FILE_VIA, else pipe
  -wait
    	with --file: wait up to 5 minutes and say whether it was read
  -wait-reply duration
    	after sending, wait this long (e.g. 10m) for the answer in the thread and print it: two agents can go back and forth without anyone relaying (exit 6 if nothing came)
  -wait-state value
    	after sending, wait until the conversation gets to this state or past it (offered|taken|ready|doing|done|stuck|declined), e.g. --wait-state ready 10m; it also ends when the other side writes, or it becomes stuck or final (exit 1)
